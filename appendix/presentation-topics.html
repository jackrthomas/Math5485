    Chapter 1: Basics of numerical analysis and floating point numbers

    1. Floating point disasters. Research a time when real world problems have occurred because floating point numbers were not handled properly (e.g. the Patriot missile failure in 1991, the Ariane 5 explosion in 1996, or the Vancouver Stock Exchange index). What went wrong, and how could it have been avoided? (Arnold, n.d.)

    2. Horner’s method. Evaluate a polynomial of degree \(n\) using only \(n\) multiplications and \(n\) additions. Compare the cost and the rounding errors with the naive approach. (Higham 2002, Ch. 5)

      TipQuick experiment 
      naive(c, x) = sum(c[k+1] * x^k for k in 0:length(c)-1)   # computes every power x^k separately
function horner(c, x)                                     # n multiplications and n additions
    p = c[end]
    for k in length(c)-1:-1:1
        p = c[k] + x * p
    end
    return p
end
c  = randn(1001)                    # a polynomial of degree n = 1000
xs = range(-1, 1, length = 10^4)
naive(c, 0.5); horner(c, 0.5)       # compile first
println("naive:  ", round(@elapsed(naive.(Ref(c), xs)), sigdigits = 2), " s")
println("Horner: ", round(@elapsed(horner.(Ref(c), xs)), sigdigits = 2), " s")
println("largest difference: ", maximum(abs.(naive.(Ref(c), xs) .- horner.(Ref(c), xs))))

      Output:

      naive:  0.56 s
Horner: 0.068 s
largest difference: 6.750155989720952e-14

      Horner’s method is several times faster…

      Plot code 
      using Plots
ns = [10, 30, 100, 300, 1000]
tn, th = Float64[], Float64[]
for n in ns

    push!(th, @elapsed horner.(Ref(cn), xs))

     label = ["naive" "Horner"], xlabel = "degree n", ylabel = "time (s)",

    3. Compensated (Kahan) summation. Adding many floating point numbers accumulates rounding error (Lecture 2). Kahan’s algorithm keeps track of the lost low order bits. Demonstrate the improvement numerically. (Kahan 1965; Higham 2002, Ch. 4)

      TipQuick experiment 
      function kahan_sum(xs)
    s = zero(eltype(xs)); c = zero(eltype(xs))   # c collects the lost low-order bits
    for x in xs
        y = x - c
        t = s + y
        c = (t - s) - y
        s = t
    end
    return s
end
xs = fill(0.1f0, 10^7)               # ten million copies of 0.1 in Float32
println("naive loop: ", foldl(+, xs))   # adds one at a time
println("Kahan:      ", kahan_sum(xs))
println("exact:      ", 10^7 * 0.1)

      Output:

      naive loop: 1.087937e6
Kahan:      1.0e6
exact:      1.0e6

      Adding one number at a time in Float32 is about 9% out; Kahan’s algorithm gets every digit right. (Julia’s built-in sum uses pairwise summation, which is another fix: compare sum(xs).)

      Plot code 
      using Plots
Ns = [10^k for k in 3:7]
err(s, N) = abs(s - N / 10) / (N / 10)
naive_err = [err(foldl(+, fill(0.1f0, N)), N) for N in Ns]
kahan_err = [max(err(kahan_sum(fill(0.1f0, N)), N), 1e-10) for N in Ns]
plot(Ns, [naive_err kahan_err], xscale = :log10, yscale = :log10, marker = :circle, lw = 2,
     label = ["naive" "Kahan (exact: error 0, drawn at 1e-10)"], xlabel = "number of terms N", ylabel = "relative error",
     title = "Summing N copies of 0.1f0")

    5. The fast inverse square root. The famous trick from the video game Quake III computes \(1/\sqrt{x}\) by reinterpreting the bits of a Float32 as an integer, followed by one step of Newton’s method. Explain why it works.

      TipQuick experiment 
      function fast_inv_sqrt(x::Float32)
    i = reinterpret(UInt32, x)               # the bits of x as an integer
    i = 0x5f3759df - (i >> 1)                # the magic step
    y = reinterpret(Float32, i)
    return y * (1.5f0 - 0.5f0 * x * y * y)   # one Newton step for 1/y^2 - x = 0
end
for x in (0.5f0, 2f0, 10f0, 1234.5f0)
    println("x = $x:  fast = ", fast_inv_sqrt(x), ",  1/sqrt(x) = ", 1 / sqrt(x),
            ",  rel. error = ", abs(fast_inv_sqrt(x) * sqrt(x) - 1))
end

      Output:

      x = 0.5:  fast = 1.4138601,  1/sqrt(x) = 1.4142135,  rel. error = 0.00024998188
x = 2.0:  fast = 0.70693004,  1/sqrt(x) = 0.70710677,  rel. error = 0.00024998188
x = 10.0:  fast = 0.31568578,  1/sqrt(x) = 0.31622776,  rel. error = 0.0017139316
x = 1234.5:  fast = 0.02846043,  1/sqrt(x) = 0.028461281,  rel. error = 2.9921532e-5

      The relative error is always below 0.2%. What happens without the Newton step? With two Newton steps?

    1. Halley’s method. Uses \(f''\) as well as \(f'\) to obtain cubic convergence. Derive it and compare with Newton’s method (Lecture 5). (Scavo and Thoo 1995)

      TipQuick experiment 
      f(x) = x^3 - 2;  df(x) = 3x^2;  d2f(x) = 6x

xn = xh = 1.0
for n in 1:4
    global xn = xn - f(xn) / df(xn)
    global xh = xh - 2f(xh) * df(xh) / (2df(xh)^2 - f(xh) * d2f(xh))

    2. Osada’s method. Newton’s method only converges linearly to a repeated root. Osada’s method recovers fast convergence for roots of known multiplicity. (Osada 1994)

      TipQuick experiment 
      # f has a double root at ξ = 1
f(x) = (x - 1)^2 * exp(x);  df(x) = (x - 1) * (x + 1) * exp(x)
x1 = x2 = 2.0
for n in 1:6
    global x1 = x1 - f(x1) / df(x1)          # Newton: linear convergence
    global x2 = x2 - 2f(x2) / df(x2)         # Newton with the multiplicity m = 2
    println("n = $n:  Newton error = ", rpad(abs(x1 - 1), 24), "modified: ", abs(x2 - 1))

    6. Brent’s method. Combines the reliability of bisection with the speed of the secant method and inverse quadratic interpolation. This (or something similar) is what most software (e.g. fzero in MATLAB or Roots.jl in Julia) uses. (Brent 1971)

    7. Newton fractals. Apply Newton’s method to \(z^3 - 1 = 0\) in the complex plane and colour each starting point by which root it converges to. Why is the boundary between the basins of attraction so complicated?

      TipQuick experiment 
      using Plots
f(z) = z^3 - 1;  df(z) = 3z^2
roots = [1, cis(2π / 3), cis(-2π / 3)]
function basin(z)
    for _ in 1:50
        z = z - f(z) / df(z)
    end
    return argmin(abs.(z .- roots))        # which root did we end up at?
end

    Chapter 3: Polynomial interpolation

    1. The equioscillation theorem. ★ In Lecture 7 we showed that the monic Chebyshev polynomial \(t_{n+1} = 2^{-n}T_{n+1}\) solves the Chebyshev problem. Equivalently, \(p^\star(x) = x^{n+1} - t_{n+1}(x)\) is the best approximation of \(f(x) = x^{n+1}\) in \(\mathcal P_n\) with respect to \(\|\cdot\|_{L^\infty([-1,1])}\). The error \(f - p^\star = t_{n+1}\) attains its maximum absolute value \(2^{-n}\) at the \(n+2\) points \(\cos\frac{j\pi}{n+1}\) with alternating signs. The equioscillation theorem says that this is not a coincidence: for any continuous \(f\) on \([a,b]\), \(p^\star \in \mathcal P_n\) is the best approximation of \(f\) if and only if there exist \(n+2\) points \(a \leq \xi_0 < \xi_1 < \dots < \xi_{n+1} \leq b\) with \[ f(\xi_j) - p^\star(\xi_j) = \pm (-1)^j \| f - p^\star \|_{L^\infty([a,b])}. \] You could state the theorem, prove the “if” direction (which uses the same sign changing argument as in Lecture 7), discuss uniqueness, and (time permitting) explain how the Remez algorithm uses the theorem to compute \(p^\star\). (Süli and Mayers 2003, Ch. 8; Trefethen 2019, Ch. 10)

    2. How does a computer compute \(\sin x\) or \(e^x\)? Range reduction followed by a carefully chosen polynomial (or rational) approximation; the polynomials are often best approximations in the sense of the equioscillation theorem. Pairs well with topic 1. (Muller 2006)

    3. Weierstrass approximation theorem and Bernstein polynomials. Every continuous function on \([a,b]\) can be uniformly approximated by polynomials. Bernstein polynomials give a constructive proof (and are used in computer graphics as Bézier curves). (Trefethen 2019, Ch. 6)

      TipQuick experiment 
      # Bernstein polynomial B_n f(x) = Σ_k f(k/n) C(n,k) x^k (1-x)^(n-k) on [0,1]
bern(f, n, x) = sum(f(k / n) * binomial(big(n), k) * x^k * (1 - x)^(n - k) for k in 0:n)
f(x) = abs(x - 0.5)
t = range(0, 1, length = 501)
for n in (10, 40, 160, 640)
    err = maximum(abs(f(s) - Float64(bern(f, n, big(s)))) for s in t)
    println("n = $n:  max error = ", round(err, sigdigits = 3))
end

      Output:

      n = 10:  max error = 0.123
n = 40:  max error = 0.0627
n = 160:  max error = 0.0315
n = 640:  max error = 0.0158

      Bernstein polynomials converge, but only like \(n^{-1/2}\) for \(|x - \tfrac12|\): quadrupling \(n\) only halves the error. Compare with Chebyshev interpolation below.

    4. Lebesgue constants. ★ The Lebesgue constant \(\Lambda_X\) measures how far interpolation on \(X\) can be from the best approximation: \(\|f - I_X f\|_{L^\infty} \leq (1 + \Lambda_X) \|f - p^\star\|_{L^\infty}\). It grows exponentially for equispaced points but only logarithmically for Chebyshev points. This explains the Runge phenomenon from Lecture 6 from a different point of view. (Trefethen 2019, Ch. 15)

      TipQuick experiment 
      # Lebesgue constant Λ_X = max_x Σ_j |ℓ_j(x)|
function lebesgue(X; m = 5000)
    t = range(-1, 1, length = m)
    maximum(sum(abs(prod((s - X[k]) / (X[j] - X[k]) for k in eachindex(X) if k != j))
                for j in eachindex(X)) for s in t)
end
println(" n   equispaced     Chebyshev")
for n in (5, 10, 20, 30)
    equi = range(-1, 1, length = n + 1)
    cheb = [cos(j * π / n) for j in 0:n]
    println(lpad(n, 2), "   ", rpad(round(lebesgue(equi), sigdigits = 4), 12), round(lebesgue(cheb), sigdigits = 4))
end

      Output:

       n   equispaced     Chebyshev
 5   3.106       1.989
10   29.9        2.421
20   10990.0     2.868
30   6.601e6     3.127

      Exponential growth for equispaced points, logarithmic growth for Chebyshev points.

      Plot code 
      using Plots

    5. Convergence of Chebyshev interpolation for functions of different smoothness. Investigate numerically how fast \(\|f - I_X f\|_{L^\infty}\) decreases for \(f(x) = |x|\), \(|x|^3\), \(\frac{1}{1 + 25x^2}\), \(e^x\), …. Explain the algebraic rates for functions with finitely many derivatives. ★ For analytic functions, explain the geometric rates using the Bernstein ellipse. (Trefethen 2019, Ch. 7-8)

      TipQuick experiment 
      # max error of Chebyshev interpolation (second kind points, barycentric formula)
function cheb_interp_error(f, n)
    x = [cos(j * π / n) for j in 0:n]
    w = [(-1.0)^j * (j == 0 || j == n ? 0.5 : 1.0) for j in 0:n]
    p(t) = (i = findfirst(==(t), x)) !== nothing ? f(x[i]) :
           sum(w .* f.(x) ./ (t .- x)) / sum(w ./ (t .- x))
    t = range(-1, 1, length = 2001)
    return maximum(abs(f(s) - p(s)) for s in t)
end
fs = [("|x|", x -> abs(x)), ("|x|^3", x -> abs(x)^3), ("1/(1+25x^2)", x -> 1 / (1 + 25x^2)), ("exp(x)", exp)]
println(rpad("n", 6), join([rpad(name, 14) for (name, _) in fs]))
for n in (8, 16, 32, 64, 128)
    println(rpad(n, 6), join([rpad(round(cheb_interp_error(f, n), sigdigits = 2), 14) for (_, f) in fs]))
end

64    0.0093        4.1e-6        2.9e-6        2.2e-15

    6. Stability of the barycentric formula. ★ In Lecture 8, the naive Lagrange formula broke down for \(n \gtrsim 800\) whereas the barycentric formula was accurate for \(n = 10\,000\). Explain why, and the difference between the “first” and “second” barycentric formulas. (Berrut and Trefethen 2004; Higham 2004)

    7. Neville’s method. A recursive way of evaluating the interpolating polynomial at a single point, closely related to the divided differences of Lecture 8. (Burden, Faires, and Burden 2016, sec. 3.2)

    8. Cubic spline interpolation. Piecewise cubic polynomials which avoid the Runge phenomenon. Constructing a spline requires solving a tridiagonal linear system. (Süli and Mayers 2003, Ch. 11; Burden, Faires, and Burden 2016, sec. 3.5)

    9. Rational interpolation. Rational functions can capture poles and sharp features much better than polynomials. For example, Floater–Hormann interpolation is a barycentric formula with different weights which works well for equispaced points. (Floater and Hormann 2007)

    10. Companion matrices. The roots of a polynomial are the eigenvalues of its companion matrix (this is what roots in Polynomials.jl and MATLAB does). For polynomials written in the Chebyshev basis, there is a similar colleague matrix. (Trefethen 2019, Ch. 18)

    11. Computing with functions: Chebfun. ★ How the Chebfun software represents functions by their Chebyshev interpolants, chooses the degree \(n\) automatically, and computes Chebyshev coefficients using the fast Fourier transform. (Trefethen 2019, Ch. 3-4)

    Chapter 4: Numerical integration

    1. Richardson extrapolation. Combine approximations computed with different step sizes to cancel the leading order error term. (Burden, Faires, and Burden 2016, sec. 4.2)

      TipQuick experiment 
      # trapezoidal rule T(h) has error ≈ C h^2, so (4T(h/2) - T(h))/3 cancels the h^2 term
trap(f, a, b, n) = (h = (b - a) / n; h * (sum(f(a + k * h) for k in 1:n-1) + (f(a) + f(b)) / 2))
I = 2.0                                   # ∫_0^π sin x dx
for n in (4, 8, 16, 32)
    T1, T2 = trap(sin, 0, π, n), trap(sin, 0, π, 2n)
    R = (4T2 - T1) / 3
    println("n = $n:  trapezoid error = ", round(abs(T2 - I), sigdigits = 2),
            ",  extrapolated error = ", round(abs(R - I), sigdigits = 2))
end

      Output:

      n = 4:  trapezoid error = 0.026,  extrapolated error = 0.00027
n = 8:  trapezoid error = 0.0064,  extrapolated error = 1.7e-5
n = 16:  trapezoid error = 0.0016,  extrapolated error = 1.0e-6
n = 32:  trapezoid error = 0.0004,  extrapolated error = 6.5e-8

      The trapezoid error decreases like \(h^2\) (divided by 4 each time), the extrapolated value like \(h^4\) (divided by 16). Repeating the idea gives Romberg integration.

    2. Romberg integration. Richardson extrapolation applied to the trapezoidal rule. (Burden, Faires, and Burden 2016, sec. 4.5)

    3. Gaussian quadrature with respect to more general weights \(w(x)\). E.g. Gauss–Chebyshev (\(w(x) = (1-x^2)^{-1/2}\)), Gauss–Laguerre and Gauss–Hermite quadrature on unbounded intervals. (Süli and Mayers 2003, Ch. 10)

    4. How to deal with improper integrals? Integrands with singularities or infinite intervals of integration: change of variables, subtracting off the singularity, … (Burden, Faires, and Burden 2016, sec. 4.9)

    5. Adaptive quadrature. Refine the mesh only where the integrand needs it. (Burden, Faires, and Burden 2016, sec. 4.6)

    6. Clenshaw–Curtis quadrature. Integrate the Chebyshev interpolant exactly. How does it compare with Gaussian quadrature? (Surprisingly well!) (Trefethen 2008; Trefethen 2019, Ch. 19)

    7. The exponentially convergent trapezoidal rule. ★ The trapezoidal rule is only second order accurate in general, but converges extremely fast for smooth periodic functions. Explain why (e.g. using the Euler–Maclaurin formula or Fourier series). (Trefethen and Weideman 2014)

    8. Monte Carlo integration and the curse of dimensionality. Quadrature rules become very expensive in high dimensions. Monte Carlo methods converge slowly, at the rate \(N^{-1/2}\), but this rate does not depend on the dimension. (Caflisch 1998)

      TipQuick experiment 
      using Random; Random.seed!(1)
# ∫ over [0,1]^d of (x_1^2 + ... + x_d^2) dx = d/3
for d in (1, 10, 100)
    exact = d / 3
    for N in (10^2, 10^4, 10^6)
        est = sum(sum(abs2, rand(d)) for _ in 1:N) / N
        println("d = $d, N = $N:  relative error = ", round(abs(est - exact) / exact, sigdigits = 2))
    end
end

    9. The Golub–Welsch algorithm. ★ The nodes and weights of Gaussian quadrature can be computed from the eigenvalues and eigenvectors of a symmetric tridiagonal matrix. Links Chapters 4 and 5. (Golub and Welsch 1969)

    10. Rodrigues’ formula for Legendre or Chebyshev polynomials. Orthogonal polynomials (whose zeros are the nodes for Gaussian quadrature) can be written as derivatives of simple functions. (Süli and Mayers 2003, Ch. 9)

    Chapter 4.5: Integrating initial value problems

    1. Runge–Kutta methods. Higher order one-step methods; the classical RK4 method and Butcher tableaux. (Süli and Mayers 2003, Ch. 12; Burden, Faires, and Burden 2016, sec. 5.4)

    2. Adaptive time stepping. Embedded Runge–Kutta pairs (e.g. the Dormand–Prince method used by ode45 in MATLAB) estimate the error and adjust the step size automatically. (Burden, Faires, and Burden 2016, sec. 5.5; Driscoll and Braun 2017, Ch. 6)

    3. Stiff equations. ★ Why explicit methods need very small time steps for some problems, and how implicit methods (e.g. backward Euler) avoid this. (Burden, Faires, and Burden 2016, sec. 5.11)

    4. Symplectic integrators. The Störmer–Verlet method conserves energy (approximately) over very long times, unlike Euler or RK4. Demonstrate with planetary orbits or a pendulum. (Hairer, Lubich, and Wanner 2003)

    3. Lanczos algorithm. ★ Approximating eigenvalues of large symmetric matrices using Krylov subspaces. (Trefethen and Bau 1997, Lecture 36)

    4. Using LU decomposition to solve a tridiagonal system of linear equations. The Thomas algorithm solves tridiagonal systems in \(O(n)\) operations (useful for cubic splines). (Burden, Faires, and Burden 2016, sec. 6.6)

    5. Linear regression. Least squares problems, the normal equations, and why we use the QR decomposition instead. (Trefethen and Bau 1997, Lecture 11; Driscoll and Braun 2017, Ch. 3)

    10. PageRank. How Google ranked web pages using the power method for computing the leading eigenvector of a (very large) matrix. (Bryan and Leise 2006)

      TipQuick experiment 
      using LinearAlgebra
# links[i] = pages that page i links to (4 web pages)
links = [[2, 3], [3], [1], [1, 3]]
n, α = 4, 0.85
M = zeros(n, n)
for (i, out) in enumerate(links), j in out
    M[j, i] = 1 / length(out)
end
G = α * M + (1 - α) / n * ones(n, n)      # the "Google matrix"
r = fill(1 / n, n)
for k in 1:50
    global r = G * r                       # power method
end
println("PageRank: ", round.(r, digits = 4))
println("check (eigenvalue 1): ", round.(G * r - r, digits = 12))

    2. The Gibbs phenomenon. Approximating a discontinuous function by Fourier series or polynomial interpolants leads to overshoots of about 9% near the jump, no matter how many terms we use. (Trefethen 2019, Ch. 9)
